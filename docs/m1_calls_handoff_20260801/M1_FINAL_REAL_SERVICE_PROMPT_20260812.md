# Стартовый промпт для Codex на M1

Работай только по ТЗ:

`tasks/_inbox_codex/2026-08-12_TZ_m1_calls_real_service_final.md`

Цель — не очередная подготовительная фаза, а кратчайший безопасный путь до
службы, которая реально обрабатывает новые звонки Mango на M1 и даёт результат
РОПу в Google Таблице и закрытом Яндекс.Диске.

Порядок:

1. Прочитай `AGENTS.md` и все источники правды проекта.
2. Сначала получи документальный commit с этим ТЗ, а также физически передай и
   проверь на основном Mac точный кодовый SHA `86ea485...` или явно названный
   более новый SHA и обезличенный audit pack. Старый SHA в локальном Яндекс Git
   сейчас не обновился.
   Запиши полученный полный SHA как `VERIFIED_TARGET_SHA`.
3. Только после проверки `VERIFIED_TARGET_SHA` создай ровно от него чистый worktree и
   ветку `codex/m1-calls-real-service-final-20260812`, затем перенеси в неё только
   документальный commit с этим ТЗ.
4. Возьми ТЗ через `scripts/task_move.py --take`, выполни lint и preflight.
5. Не строй новый конвейер. Переиспользуй существующий живой путь и исправляй
   только доказанные блокеры ТЗ.
6. Обязательно проведи один независимый аудит фактических результатов 10
   звонков. Дополнительных проверяющих и Claude подключай только к найденным
   рискам, а не вместо реального запуска.
7. Все кодовые, тестовые, конфигурационные и dry-run шаги выполни
   самостоятельно без остановки.
8. Остановись только перед явно запрещёнными live-шагами и дай Дмитрию одну
   точную команду подтверждения для ближайшего шага:
   - подготовка owner-only runtime без обработки;
   - один изолированный полный цикл: read-only Mango, одна allowlisted запись,
     ASR+Resolve+Analyze без изменения production cursor;
   - обработка контрольных 10 звонков;
   - публикация контрольных 10 строк Google/Яндекс;
   - перенос runtime и единый cutover;
   - read-only Mango API и закрытие разрыва;
   - временный launchd на сутки;
   - временное продление ещё на 72 часа;
   - постоянный launchd после трёх дней.
9. После каждого подтверждения продолжай до следующего наблюдаемого результата,
   а не возвращайся к архитектурному планированию.
10. AMO, Tallanto write и production Customer Timeline должны оставаться OFF.

Главный принцип: `1 звонок -> нулевой повтор -> 10 звонков -> сутки -> 3 дня ->
постоянная служба`. Первая бизнес-польза появляется после 10 проверенных
звонков; для неё не ждать семидневного испытания.

Финальный ответ Дмитрию пиши просто по-русски:

- что реально работает;
- сколько звонков получено/готово/в карантине/потеряно;
- что увидел РОП;
- какие проверки пройдены;
- какая одна команда или ручное действие требуется дальше.
