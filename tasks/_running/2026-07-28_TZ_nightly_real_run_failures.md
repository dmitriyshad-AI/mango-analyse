# ТЗ: закрыть дефекты реального ночного прогона 2026-07-28

## Сырой факт

Прогон `run_20260728T003001Z` на staging показал:

- AMO leads остановились на 20 страницах / 1000 строках;
- Wappi прочитал 39 034 сообщения, но не записал ни одного из-за неполной привязки части чатов и конфликтов уже существующих связей;
- конфигурация не содержала уже реализованный `checkpoint_dir` Wappi и сохранила отсутствующий путь почтовой карты;
- Tallanto отдельно падает по авторизации и этим ТЗ не чинится.

## Образ результата

1. Изменение состава канонической конфигурации обязательно инвалидирует старый JSON и пересобирает его.
2. AMO за один проход может дочитать до 5000 строк на endpoint (100 страниц по 50), не меняя read-only контракт.
3. Wappi при `require_widget_linkage=false` импортирует все безопасные записи, а непривязанные оставляет `pending_attribution`; конфликт существующего клиента остаётся на прежнем клиенте и создаёт конфликт для разбора, но не блокирует весь пакет.
4. При `require_widget_linkage=true` прежний строгий режим сохраняется.
5. Отправка сообщений, запись в AMO/Tallanto/CRM и доступ бота к непроверенной истории остаются невозможны.

## Минимальное решение

- поднять версию схемы ночной конфигурации;
- в builder установить AMO `max_pages=100`, Wappi `require_widget_linkage=false`;
- считать неполную widget-привязку блокером только в строгом режиме;
- не превращать уже покарантиненный `existing_customer_conflict` в блокер всего пакета;
- добавить регрессии на generated config и частичный безопасный импорт.

## Не делать

- не ослаблять проверку полноты каталога/страниц/запросного бюджета;
- не перепривязывать конфликтные события автоматически;
- не включать историю Wappi в bot-safe контекст;
- не трогать prod/runtime и внешние системы;
- не чинить Tallanto-токен кодом.

## СТОП

- любое изменение prod/runtime или попытка записи во внешнюю систему;
- потеря прежней связи события с клиентом;
- неполная пагинация или сетевой предел, ошибочно объявленные успехом;
- красный точечный или полный тест.

## Приёмка

- точечные тесты зелёные;
- полный pytest зелёный;
- повторный staging-прогон показывает AMO complete либо новый честный предел, Wappi `writes_applied>0`, почтовый enrich не падает на отсутствующем альтернативном пути;
- unresolved/conflict счётчики сохранены в отчёте;
- один коммит в main, push origin+yandex.
