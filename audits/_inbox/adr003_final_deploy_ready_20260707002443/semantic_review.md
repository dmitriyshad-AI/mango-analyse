# Semantic Review

Verdict: `PASS_WITH_NOTES`.

Что прошло:

- Paid/no-access и receipt-not-credited больше не получают ложный возвратный текст. Клиент видит безопасную формулировку: оплату нужно сверить в системе, менеджер ответит по точным данным.
- Настоящий запрос возврата остается ручным refund-сценарием: маршрут `manager_only`, без обещания суммы, срока или результата.
- Налоговый/возвратный конфликт покрыт инвариантом SemanticFrame: frame владеет смыслом клиентского шаблона, legacy может только ужесточить маршрут.
- P0 child-safety кейс после исправления не консультирует и не собирает детали до менеджера.
- Валидный P0 SemanticFrame без legacy-P0 metadata теперь не может остаться self-route: маршрут ужесточается до `manager_only`.
- В проверенных smoke-примерах нет смешения брендов, неподтвержденных чисел, обещаний возврата/доступа/зачисления оплаты.

Неблокирующие риски:

- Часть ответов остается шаблонной и повторяется на втором ходе; это приемлемо для P0/manager-only, но ухудшает тон.
- Moratorium snapshot обновлен не только по текущему payment-фиксу, но и по уже существующим изменениям ветки `policy_routing.py` из предыдущих блоков. Это не новый понимающий regex в данном фиксе, но требует прозрачного регрейда.
- Smoke локальный, не M1; он проверяет деплой-кандидат, но не заменяет большой replay exam.

Обязательные регрессии:

- paid_no_access / receipt_not_credited / paid_lesson_missing -> `manager_only`, `payment_dispute` text, без слова "возврат".
- real_refund/dispute -> `manager_only`, refund-safe text, без обещания результата.
- `correct_route_wrong_p0_text` для tax/refund/payment конфликтов.
- valid SemanticFrame P0 manager-only -> `manager_only` route и нейтральный manager text без консультации и сбора деталей.
