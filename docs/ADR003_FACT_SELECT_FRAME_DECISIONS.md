# ADR-003 Fact Select Frame Decisions

Дата: 2026-07-07.

## D-001. SemanticFrame не выбирает факты до retriever

Решение: не строить pre-selection до `_direct_path_llm_retrieve_fact_pack`.

Причина: продуктовый смысл `requested_product` появляется в том же LLM retriever-вызове, где выбираются факты. Использовать его "до" retriever означало бы либо второй LLM-вызов, либо чтение не того источника. Поэтому слой сделан как post-selection: сначала текущий retriever выбирает id, затем `requested_product` осторожно переранжирует exact/adjacent.

## D-002. Apply строго default-OFF

Решение: `TELEGRAM_FACT_SELECT_FRAME` выключен по умолчанию и не входит в `pilot_gold_v1`.

Причина: флаг меняет состав фактов, а значит может менять клиентский текст. До M1-пары и регрейда допустимы только явная локальная активация и trace-only класс `fact_select_read`.

## D-003. Trace-only без поведения и без prompt-change

Решение: `fact_select_read` добавлен как semantic reading class. Он пишет `semantic_reading_trace`, но не меняет fact pack и не расширяет prompt retriever-а.

Причина: нужен быстрый способ измерить согласие frame и текущего выбора фактов без риска для маршрута/текста. Если trace-only просит модель о новых полях, это уже может изменить основной выбор, поэтому такой путь запрещён.

## D-004. Fail-closed коридор

Решение: если нет продукта, низкая уверенность, конфликт осей, чужой бренд, неканонический enum, нет совпадающего факта или apply выключен, сохраняется baseline.

Причина: выбор фактов влияет на правдивость ответа. Лучше оставить старый набор фактов, чем уверенно подложить неверный факт.

## D-005. Без новых regex/marker-правил смысла

Решение: новый слой не добавляет новые regex или marker-таблицы понимания клиентского смысла. Проверка предмета использует существующий matcher, а формат/площадка/тип продукта принимаются только в канонических enum-значениях схемы и сверяются по структурным полям фактов.

Причина: цель ADR-003 — не нарастить новую лазанью. Локальный детерминизм здесь только проверяет структурную совместимость уже выбранных фактов.

## D-006. Venue-scope закрыт в keyword fallback

Решение: если LLM retriever понял `requested_scope`, но вернул пустую выборку и код ушёл в keyword fallback, fallback теперь тоже применяет venue-scope.

Причина: прежняя дыра теряла уже понятый scope и могла снова сделать факт чужой площадки exact.

## D-007. Complaint handoff literal

Решение: существующий `COMPLAINT_SAFE_TEXT` сделан нейтральным: без "понимаю", извинений, сожалений и сбора деталей.

Причина: полный тест ТЗ поймал pre-existing safety-хвост: маршрут был безопасный, но текст нарушал уже существующий complaint-регресс.
