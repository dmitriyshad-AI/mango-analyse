# Промпт для нового диалога Codex на M1

```text
Работай только по треку Mango Calls. Customer Timeline и другие треки не трогай.

Получи из Git ветку:
codex/calls-provider-selective-pilot-20260822

Точный ожидаемый SHA Дмитрий передаст отдельной строкой вместе с этим промптом.
Сначала выполни fetch и проверь побайтное совпадение `git rev-parse HEAD` с этим
SHA. Создай отдельную ветку `codex/m1-provider-selective-pilot-20260822` и
отдельный чистый worktree. Исходную ветку, main, живой worktree и launchd не
изменяй.

Полностью прочитай:
1. AGENTS.md
2. README.md
3. ARCHITECTURE.md
4. docs/PROJECT_NOW.md
5. docs/RUNBOOK.md
6. docs/DECISIONS_LOG.md, особенно D-120–D-124
7. docs/mango_calls_handoff_20260816/M1_QUALITY_V3_INTEGRATION_PROMPT.md
8. docs/mango_calls_handoff_20260816/M1_GOOGLE_UTM_CUTOVER_2026-08-22.md
9. docs/mango_calls_handoff_20260816/M1_PROVIDER_SELECTIVE_PILOT_TZ_2026-08-22.md

Выполняй новое ТЗ последовательно. Не дублируй уже реализованные Mango-клиент,
publisher, базу или службу. Сначала инвентаризация и офлайн-тесты.

Известный внешний блокер: 22.08.2026 read-only запросы 1 и 10 реальных
recording_id на исходном Mac вернули только `{"result":5008}` — метод отказал
текущему ключу, точная причина ещё не подтверждена Mango. Повторная проверка
23.08.2026 на одном ID дала тот же ответ, поэтому
ступень 10 намеренно не повторялась. Пока Дмитрий не подтвердит подключение
услуги и отдельно не разрешит новую сетевую проверку, не повторяй Mango API и
не запускай по кругу retries.
`MANGO_PROVIDER_TRANSCRIPTS` обязан оставаться выключенным; его владелец —
Дмитрий, а точка закрытия — решение после замера 100 новых звонков.

Жёсткие запреты до отдельных разрешений Дмитрия:
- не запускать ASR;
- не запускать реальный Resolve/Analyse;
- не менять рабочую SQLite;
- не менять launchd и живую службу;
- не писать в Google, AMO и Tallanto;
- не включать Selective по умолчанию;
- не возвращать исторические completed/published строки в очередь.

После разрешения сетевой проверки выполняй только лестницу Mango 1 → 10.
Требуется result=1000 и точная связь каждого ответа с запрошенным recording_id.
5008, неизвестная схема, дубли, пропуски или лишние ID означают STOP без догадок.
До запроса проверь уже реализованный исполнимый лимит/белый список: больше 10 ID
должны дать явный STOP до сетевого запроса, разрешены только ID из
`MANGO_PROVIDER_TRANSCRIPTS_ALLOWLIST`. Отчёт первых десяти обязан
показывать оценки сопоставления физической дорожки с ролями Mango и причины
`untrusted`. Mango даёт ролевые реплики, а не готовый номер дорожки.

После отдельного разрешения на пилот накопи 100 новых звонков после включения
provider evidence и используй только копию БД и сохранённые пары Whisper/GigaAM.
Повторный ASR запрещён. A/B должен быть вложенным 20 → 50 → 100,
с одинаковыми входами и максимум одним вызовом лёгкой модели на реально
эскалированный звонок. До первого вызова реализуй устойчивый журнал точных
input/output токенов Resolve; неизвестный расход не считать нулём. В baseline
режим `off`, в эксперименте `selective`; всё остальное, включая evidence,
одинаково. Любая выдумка или смена роли/порядка/факта означает STOP.

До provider-пилота сделай копию рабочей SQLite, выполни штатный
`init-db` только на копии и докажи наличие `source_recording_id` и уникального
индекса. Текущая исходная база этого столбца не содержит; обычный process A с
выключенным provider-захватом от этого не блокируется. Живую базу этим промптом
не менять.

Google-проверку делай только на отдельной вкладке, которую создаст Дмитрий, и
только после смыслового PASS. Ступени 1 → 10 → 25, старый и новый вариант одного
звонка рядом, первые 16 столбцов неизменны, 17-й — основания, 18-й — UTM. После
каждой записи — полный readback. Основной лист не трогай. Не используй основной
publisher для парных строк. Обычные 18 столбцов и UTM уже реализованы, их не
переписывай. Только после реального A/B создай отдельный узкий писатель с ключом
`(call_key, variant)`.

Факты исходного Mac, которые надо воспроизвести до любых live-действий:
- 6 383 строки прошли полный read-only регрейд классификации;
- итоговые 24 изменения прочитаны Claude: 16/16 роботов правильно стали
  `non_conversation`, 8/8 административных звонков правильно стали
  `service_call`;
- короткий живой контакт без содержания не считается сервисом, а помечается для
  ручной проверки;
- на полном сохранённом контексте ручная проверка изменилась с 828 до 1 013
  строк из 4 966: 190 добавлено, 5 снято; исторические данные не переписаны;
- новое правило классификации не закрыто отдельным флагом: до развёртывания
  измерь этот же баланс на копии M1-базы; откат возможен только Git-ревизией;
- проверь дубли `source_recording_id` как внутри новой партии, так и против всей
  уже сохранённой базы; конфликт должен быть пропущен и отражён в отчёте;
- проверка пригодности 20 → 50 → 100 дала 0 доверенных ролей, 0 запусков
  Resolve и 0 модельных вызовов; это STOP, не A/B качества;
- локально прошли 1 052 теста единым прогоном, один штатно пропущен; повторить на
  Python 3.12.

Используй Claude CLI Opus с максимальной глубиной для независимых проверок:
архитектор, ломатель, бизнес-аудитор и маниакальный уборщик. Не принимай его
выводы на веру: каждое замечание проверь в коде и сыром артефакте. Не передавай
Claude секреты. Принятые ошибки закрепляй тестом, гейтом или ручным контролем.

По завершении каждой фазы верни:
1. фазовый GO/STOP;
2. ветку и точный SHA;
3. что реально запускалось и что не запускалось;
4. команды и результаты тестов;
5. числа read-only проверки без текстов и телефонов;
6. список изменённых файлов;
7. отчёты Claude и своё решение по каждому замечанию;
8. известные ограничения и следующий минимальный шаг.

Ничего не сливай в main и не разворачивай в production без отдельного разрешения.
```
