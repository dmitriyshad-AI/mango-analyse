## B. Ступень 1 — один звонок

Ступень 1 и всё, что дальше, запускается **только с отдельного разрешения Дмитрия на эту
ступень**: здесь начинается работа с реальными данными (Mango API, распознавание,
Resolve, Analyse).

**Блокер, который снимается до этой ступени.** Пока слой захвата не сохраняет ответ Mango
о сторонах, проверка возвращает `provider_evidence_missing`, и **ни один реальный звонок
не станет доверенным**: все строки будут «Спикер A/B» без результата, возражения,
следующего шага и срока, а модель вызвана не будет. Это не дефект и не повод продолжать
«как есть» — без доработки захвата (раздел 4 передачи) ступени 1–6 бессмысленны, потому
что измерять будет нечего.

- [ ] Взят обычный двусторонний звонок с раздельными дорожками.
- [ ] Provider evidence Mango получен и сохранён; сырое тело первого ответа приложено.
- [ ] Прогнан **только** этот звонок через штатные стадии.
- [ ] Ручная сверка с аудио: ни одна реплика не пропала, не переставилась и не
      приписана другой стороне.
- [ ] Роли совпали с аудио.
- [ ] Результат, оплата, возражение, следующий шаг и срок — у каждого есть ссылка на
      существующую реплику **этого же** звонка, цитата и таймкод.
- [ ] Время в отчёте — московское.
- [ ] Расход: 1 обращение `compact`; факт эскалации в `full` зафиксирован явно (да/нет).
- [ ] Обращений Resolve к модели: 0.

**STOP:** хоть одна реплика потеряна; роль не совпала с аудио; вывод без ссылки;
второй Google-writer; телефон или текст разговора в логе.

## G. Что проверяет РОП (и как это засчитывается)

Проверку делает **один заранее назначенный РОП**, правильные ответы фиксируются
**до** начала проверки.

- [ ] На выборке 50 доверенных звонков: минимум **48 из 50** — за 30 секунд, без
      полной расшифровки, РОП правильно отвечает на два вопроса:
      «чем закончился разговор?» и «какой следующий шаг?».
- [ ] РОП отдельно подтверждает по каждому проверенному звонку:
  - видно, что было в разговоре;
  - видно, что подтверждено ссылкой, а что нет (столбец «Основание ключевых выводов»);
  - видно, требует ли звонок ручной проверки, и почему;
  - следующий шаг выполним и не противоречит содержанию разговора.
- [ ] На выборке недоверенных: РОП подтверждает, что строка **честно** сообщает
      «стороны не подтверждены, нужна ручная проверка», а не выглядит пустой ошибкой.
- [ ] Ни в одной строке нет колонки «Нужна проверка = Нет» при непустой причине
      проверки.

**Стоп-условия РОПа:** вывод противоречит аудио; в отчёте появилась продажа, которой
не было; следующий шаг относится к другому клиенту; в тексте оказался телефон или
почта.

## H. Бюджет: сколько обращений к модели допустимо

Бюджет считается **в обращениях к модели**, потому что Codex CLI точные токены не
возвращает. Цифры ниже — предложение к утверждению Дмитрием до ступени 4.

| Сценарий | Ожидаемые обращения Codex | Допустимо максимум | Что означает превышение |
|---|---|---|---|
| 1 доверенный содержательный звонок | 1 (`compact`) | 2 (`compact` + одна эскалация `full`) | 3 и больше = скрытый повтор, STOP |
| 1 недоверенный звонок | 0 | 0 | любое обращение = дефект защиты, STOP |
| 1 доказанно несодержательный звонок | 0 | 0 | любое обращение = детерминированный гейт не сработал, STOP. Проверить, что `TELEGRAM_NON_CONVERSATION_ADVISORY` выключена: она отключает этот пропуск и возвращает такие звонки в модель |
| Повтор того же звонка (служба) | 0 | 0 | обращение = сломан пропуск неизменного |
| Повтор того же входа (прямой Analyse) | 0, `cache_hit=true` | 0 | обращение = сломан ключ кэша |
| 10 звонков (все доверенные) | 10 | 13 (доля эскалаций ≤ 30%) | доля эскалаций > 30% = разбираться до ступени 4 |
| 50 доверенных | 50 | 65 (эскалаций ≤ 30%) | > 65 = STOP, бюджет пересогласовывается |
| 50 недоверенных | 0 | 0 | > 0 = STOP |
| Resolve на любой ступени | 0 | 0 | > 0 = `RESOLVE_LLM_PROVIDER` не `off`, STOP |
| Google-выгрузка на любой ступени | 0 | 0 | > 0 = появился второй путь, STOP |

Форма отчёта по расходу (одна таблица на ступень, без ПДн):

```text
Ступень: ___            Дата: ___         Знаменатель: ___ звонков
Окружение: RESOLVE_LLM_PROVIDER=___  ANALYZE_PROVIDER=___
           ANALYZE_PROMPT_PROFILE=___  ANALYZE_ESCALATE_FULL_ON_AMBIGUITY=___
           LLM_CACHE_ENABLED=___  TELEGRAM_NON_CONVERSATION_ADVISORY=___

Звонков всего                                  ___
  из них недоверенные (0 вызовов)              ___
  из них несодержательные (0 вызовов)          ___
  из них взято из кэша                         ___
  из них реально вызвали модель                ___

Обращений compact                              ___
Обращений full (эскалация)                     ___   доля от доверенных ___%
Обращений Resolve к модели                     ___   (обязано быть 0)

По каждому provider/model/prompt_version:
  exact ___ + partial ___ + unavailable ___ = model_calls ___
  model_usage_balanced = ___   identity_balanced = ___

Журнал попыток: уникальных attempt_id ___,
  в состоянии reserved ___ (обязано быть 0),
  в состоянии indeterminate ___ (обязано быть 0)
```

**Как читать `unavailable`.** Для Codex это норма, а не ошибка: провайдер токены не
сообщает, система честно это пишет. Сверять расход с фактическим биллингом провайдера
за окно прогона — единственный способ получить денежную цифру. Оценивать токены по
количеству символов **запрещено**.

**Первый прогон холодный.** Версия промпта изменилась (`v6→v8` compact, `v7→v9` full),
поэтому старые совпадения кэша не сработают. Изменение модели, версии промпта, входа
или параметров запуска сбрасывает совпадение кэша всегда.

## I. Общие стоп-условия (действуют на любой ступени)

- Пропала или переставилась реплика.
- «Менеджер/Клиент» без связанного с этим звонком ответа Mango.
- Provider evidence можно перепривязать к другому звонку или записи.
- Два звонка с одним непустым `source_recording_id`.
- Рискованный вывод без точной ссылки на реплику.
- Недоверенный звонок получил коммерческий вывод или вызвал модель.
- Повтор вызвал модель или создал дубль.
- Баланс не сходится; в журнале попыток есть `reserved`, `indeterminate` или дубль ID.
- Найден второй Google-writer или два владельца службы.
- В логе или инциденте есть телефон, почта или текст разговора.
- Изменён исходный звук, результат распознавания, исходные реплики или Resolve evidence.
