# ТЗ: полный сезонный охват Wappi с ранней бизнес-пользой

## Образ результата

РОП открывает один лист `Wappi`. Одна строка соответствует одному личному чату.
Строка содержит точную ссылку AMO, краткое досье, решение писать/не писать,
персональное сообщение и доказанную актуальность. Менеджер проверяет строку и
отправляет сообщение вручную. Клиентские сообщения и CRM автоматически не меняются.

Польза появляется ступенями: сначала принятая двадцатка, затем 100, 500 и весь
свежий реестр N личных чатов. 4 358 — только базовый снимок на 09.08,
а не финальный знаменатель. Полный массив не блокирует готовые строки.

- KB v6.8.

## Выбранное решение

Рассмотрены варианты:

1. Новый продуктовый фреймворк кампаний — отклонён как лишний.
2. Продолжать четыре одноразовых скрипта аудита — отклонён: они дублируют код,
   содержат смысловые regex и не дают устойчивого повтора.
3. Один долговечный CLI-оркестратор поверх существующих readers/helpers — выбран.

CLI обязан только:

1. локально соединять чат, точную AMO-связь, свежие AMO/Tallanto-дельты и звонки;
2. формировать компактный пакет для LLM без повторного скачивания неизменного;
3. принимать структурированный вердикт LLM и строить 28 колонок;
4. обновлять строку по `profile_id:chat_id`, читая ручные X:Y как приоритетное
   состояние и никогда не включая их в записываемые диапазоны;
5. считать отпечаток Wappi+AMO+Tallanto+Calls и не вызывать LLM повторно при
   неизменном отпечатке.

LLM понимает смысл переписки и звонков. Детерминизм проверяет только ключи,
закрытый баланс, схему, уникальность, свежесть и сохранение ручных полей. Новые
regex для намерения, теплоты, отказа, маршрута и текста запрещены.

## Лестница

### S20

- принять пакеты M1 по SHA;
- обновить 20 существующих строк по данным до 22–23 августа;
- для каждой связанной телефонной истории прочитать полный свежий звонок;
- получить отдельный смысловой аудит;
- записать 20/20 строк как очередь РОПа с сохранением X:Y;
- статус `ОТПРАВИТЬ` не отменяет обязательную проверку последних сообщений Wappi.

### S100

- выбрать оба бренда, Telegram/MAX, точную одиночную сделку, несколько сделок,
  отсутствие связи, семейный телефон, оплату/запись и отказ;
- баланс: `100 = готово + не писать + проверка + ошибка`; ошибка одного LLM-вердикта
  даёт видимую строку `ПРОВЕРКА` без клиентского текста и не останавливает остальные;
- два одинаковых запуска дают те же ключи, корзины и отпечатки;
- чужих клиентов, дублей и записанных в `ОТПРАВИТЬ` — 0.

### S500 и SALL

- расширять только после прохода предыдущей ступени;
- N каждый раз получается новым полным аудитом личных чатов;
- строк столько же, сколько уникальных ключей;
- gap/conflict остаются видимыми строками `ПРОВЕРКА`, не исчезают;
- после полного прохода читать только дельты и пересобирать только изменившиеся
  строки.

## Бизнес-правила

- не писать оплатившим и записанным в будущую группу, даже без оплаты;
- не писать при прямом отказе, незакрытой жалобе/возврате, активной работе
  менеджера, тестовом/служебном/групповом чате;
- отсутствие личного повода не является стопом: LLM готовит честный сезонный
  повод;
- общий семейный телефон даёт семейный контекст, но не приписывает факт ребёнку;
- любое новое сообщение, звонок, сделка или карточка переводит строку в
  `ОБНОВИТЬ`;
- автоматическая отправка клиентам запрещена.
- `B` хранит рекомендацию машины, `X` — решение РОПа, `Y` — фактический ход кампании;
  `КУПИЛ`, `СТОП`, `ОТВЕТИЛ` и отправленные касания не затираются новым вердиктом.

## Приёмка каждой ступени

1. Формальный проход: схема 28 колонок, уникальный ключ, закрытый баланс.
2. Данные: точные SHA/время/режим источников, 0 внешних записей.
3. Сквозной проход: реальный текст виден в конечном Google-листе.
4. Отрицательные контроли: чужой клиент; семейный телефон; записан/оплатил;
   отказ; новый входящий после подготовки строки.
5. Повтор: 0 новых бизнес-строк и 0 повторных LLM-вызовов без изменения входа.
6. Смысловой проход: РОП может отправить текст без переписывания; факты, бренд,
   адресат, предмет и следующий шаг не выдуманы.

## СТОП и ограничения

- источники только read-only; в AMO, Tallanto, Wappi и клиентам не писать;
- Google-лист изменяется только по явному запросу этой задачи;
- X:Y не перезаписывать;
- не копировать большие базы, если достаточно ссылки с SHA;
- не строить повторно Customer Timeline;
- не переносить legacy regex-гейты из одноразового аудита.
