# ТЗ: актуальное состояние Mango и переаудит остатка уборки

## Проблема

Последний владелецкий документ состояния и карта модулей D1 построены на старых
SHA. После них в `main` вошли большие волны удаления, модельный direct-path и
исправления Customer Timeline. Старые проценты и списки кандидатов нельзя
использовать как актуальную истину.

## Образ результата и бизнес-польза

Владелец получает один актуальный документ, где простым языком разделены:

1. уже работающие механизмы;
2. код, доказанный тестами, но не включённый в runtime;
3. блокеры пилота и Customer Timeline;
4. подтверждённый остаток безопасной уборки;
5. следующие действия, отсортированные по влиянию на ИИ-сотрудника.

Документ не должен считать зелёные тесты доказательством бизнес-готовности и не
должен предлагать удаление только по статическому сканеру.

## Порядок

1. Зафиксировать `main` SHA, runtime, свежий nightly и текущую очередь ТЗ.
2. Пересчитать изменения после предыдущего владелецкого отчёта.
3. Сверить карту D1 с Graphify текущего SHA, исходниками и точками запуска.
4. Получить независимые вердикты архитектора, ломателя, бизнес-аудитора и двух
   уборщиков; отдельно запросить Claude CLI.
5. Для каждого кандидата разделить `удалено`, `сохранить`, `аудировать`,
   `можно удалить после доказательства`.
6. Обновить владелецкий документ и создать audit pack.

## Приёмка

- каждое ключевое число имеет SHA, путь/время данных и режим запуска;
- текущий runtime не смешан с возможностями свежего `main`;
- статус regex/LLM и Customer Timeline подтверждён живыми точками входа;
- карта D1 помечена как историческая, а её кандидаты повторно проверены;
- для удаления нет разрешения без Graphify, сырого исходника, точки запуска и
  отрицательного теста;
- перечислены непроверенные риски и конкретный следующий замер;
- создан один audit pack и обновлён один канонический владелецкий документ.

## СТОП

- обнаружена новая грязь вне заявленных зон;
- для вывода требуется write в runtime, AMO, Tallanto или CRM;
- кандидат на удаление не подтверждён текущими исходниками и точкой запуска;
- основной `main` изменился во время замера так, что SHA отчёта стал неверным.

## Бритва

Новый код не писать. Сканер D1 не переносить автоматически: для текущего
решения достаточно Graphify, `rg`, Git и существующих тестов. Новый файл отчёта
нужен, потому что прежняя версия должна оставаться воспроизводимой историей.
