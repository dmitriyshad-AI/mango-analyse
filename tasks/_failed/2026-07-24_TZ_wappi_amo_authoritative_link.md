# Production Customer Timeline и ИИ-сотрудник для всех личных Wappi-диалогов

## Решения владельца от 2026-07-24

- Коммерческая сущность — семья/родитель; ученики, сделки, оплаты, занятия и коммуникации находятся внутри семьи.
- В Timeline загружаются все реальные AMO/Tallanto-контакты; приоритет обработки — актуальные. Типы Tallanto «11 класс» и варианты «выпускник» сохраняются, но не входят в первоочередную коммерческую выборку.
- Разрешено обновлять рабочую Customer Timeline данными из AMO, Tallanto, Wappi, почты и звонков.
- Разрешено писать черновики в AMO для всех личных входящих Wappi-диалогов без белого списка и лимита по числу клиентов.
- Отправка сообщений клиентам пока запрещена.
- Для Wappi используется авторитетная связь виджета с AMO contact/leads. Нужно исчерпать прямые AMO/Wappi-идентификаторы; имя само по себе не является связью.
- Из будущей реактивации исключаются opt-out/no-contact, сотрудники, тесты, системные записи, открытые жалобы, возвраты и юридические конфликты.
- Предложение выбирается по подтверждённым интересам, возрасту, филиалу, предметам, расписанию, оплатам и истории; наличие мест по умолчанию считается положительным, если нет явного подтверждения обратного.

## Бизнес-результат

1. Одна рабочая Customer Timeline содержит AMO, Tallanto, звонки, почту, Telegram/MAX Wappi, оплаты, карточки и посещения.
2. Каждый личный входящий Wappi-диалог получает досье и черновик в AMO; клиенту ничего не отправляется.
3. Владелец получает открываемый XLSX по 50 актуальным потенциальным семьям без маскирования ПДн, с доказательствами и персональным предложением.
4. Никакой второй runtime-системы, новой постоянной ветки, новой зависимости или россыпи флагов не создаётся.

## Последовательность

### 0. Честный baseline

- Зафиксировать количество семей/взрослых/учеников и событий по источникам в текущей staging и рабочей Timeline.
- Проверить фактические источники и курсоры; обновить Tallanto read-only, если выгрузка 10.07.2026 устарела и штатный API доступен.
- Зафиксировать Wappi personal chats по всем профилям и баланс exact/missing/conflict без вывода ПДн.

### 1. Исправить идентификацию до рабочей записи

- Не повышать одиночный email или RFC Message-ID цепочки до strong identity без подтверждающего сигнала.
- Нормализовать телефонные link types при проверке shared identity.
- Не допускать неизвестный identity_authority как strong.
- События с `brand_context_authorized=false` не должны попадать в bot-safe контекст.
- Отзыв bot-context не должен удалять активное событие из FTS.
- Все изменения ingestion-run завершаются success/failed без вечного `running`.

### 2. Авторитетная привязка Wappi -> AMO -> Timeline

- Переиспользовать точный read-only контракт браузерного виджета Wappi: `POST /amocrm/contact/find`, профильный Wappi-токен в `Authorization` и теле, `crm_id`, `profile_uuid`, `platform`, `chat_id`.
- Для каждого personal chat получить `amo_contact_id` и все `amo_lead_id`; несколько сделок одного контакта не являются конфликтом личности.
- Перепривязать старые unmatched-события локально, даже если они вышли из сетевого окна загрузки.
- Повторный проход не создаёт дублей и даёт ноль изменений.
- Для каждого остатка missing сохранить техническую причину и исчерпать прямые AMO/Wappi ID до вывода «нет связи».

### 3. Полное обновление рабочей Timeline

- Идемпотентно загрузить актуальные AMO, Tallanto, звонки, почту и всю историю Wappi Telegram/MAX.
- Tallanto является источником оплат/абонементов/посещений, AMO — контактов/сделок/карточек, каналы — истории общения.
- Конфликтующие факты не затирать; хранить источник и время.
- После применения: `quick_check`, foreign keys, дубли, повторный проход с нулевыми изменениями, coverage по каждому источнику.

### 4. Досье и коммерческий XLSX

- Построить досье на 50 актуальных потенциальных семей; 11 класс/выпускники не входят в приоритет.
- Включить реальные ФИО, телефоны, email, учеников, AMO-сделки, оплаты, посещения, историю каналов, интересы, возражения, следующий шаг и подтверждённое предложение.
- Каждый вывод имеет источник/дату/доказательство; технические поля вынести на отдельный лист.
- Провести независимый смысловой аудит строк «вопрос/история -> вывод -> предложение».

### 5. Черновики для всех личных Wappi-диалогов

- Убрать ограничение allowlist только для draft-note режима.
- На каждый новый personal inbound строить контекст из Timeline и писать идемпотентный черновик в связанную AMO-сделку/контакт.
- Не отправлять Wappi/Telegram/MAX сообщения клиентам.
- Сохранить P0, бренд, ПДн, no-contact и анти-выдумку как детерминированные полы.
- Смысл вопроса и выбор ответа/предложения должны опираться на LLM semantic reading, а не на подстрочные бизнес-маркеры.

## Приёмка

- Целевые и полный pytest зелёные.
- Рабочая Timeline проходит SQLite `quick_check`, foreign keys и идемпотентный повтор.
- Баланс источников и Wappi-привязки сходится; нет молча потерянных записей.
- На owner-50 нет ложной семьи, чужого бренда, выдуманной цены/даты/предмета/посещения.
- Черновик появляется в AMO для каждого нового допустимого personal inbound; повтор не создаёт вторую заметку.
- Ни одного клиентского send; AMO readback подтверждает только заметки-черновики.
- Итоговая ветка вливается в `main`; временный worktree удаляется после регрейда и проверки runtime.

## СТОП

- Авторитетный Wappi contact противоречит UI AMO или ведёт к нескольким разным семьям.
- Для записи требуется отправка клиенту или изменение Tallanto/CRM-данных.
- Найдена ложная склейка семьи, чужой бренд, P0-промах или выдуманный коммерческий факт.
- Нет однозначного способа readback/идемпотентности AMO note write.
