# ТЗ: вернуть полезный конспект и очистить UTM
## Проблема

В реальном пилоте 17/25 строк получили заглушку вместо конспекта. Полный диалог
содержит очевидные договорённости, но v3 запрещает модели писать связный
конспект, а `manager_brief` использует только узкий набор полей. В UTM-ячейку
попадают внутренние сведения о способе сопоставления с AMO.

## Решение

1. Сохранить строгую проверку оплат, результата, возражений, срока и следующего
   шага по точным репликам.
2. Вернуть в единственный ответ Analyze отдельный связный конспект 3-5
   предложений на основе полного диалога. Второй модельный вызов не добавлять.
3. Конспект не должен содержать техническую заглушку, дамп диалога, придуманные
   факты или противоречить проверенным полям.
4. В Google показывать нормальный конспект. `manager_brief` оставить только как
   резерв для старых записей.
5. В UTM-ячейке показывать только найденные `utm_*` и `url`. Если надёжно
   сопоставленная заявка не содержит меток и страницы — `UTM не найдены`; если
   заявка не сопоставлена однозначно или AMO недоступна — `UTM не определены`.
   Подробная причина остаётся в сыром кэше и отчёте, но не показывается РОПу.
   Сырой кэш и внутренние счётчики связи не менять: очищать только отображение
   при построении строки Google.
6. Зафиксировать гибридный контракт в `DECISIONS_LOG.md`: свободный конспект
   разрешён только как управленческий текст, а критичные поля по-прежнему
   публикуются только после отдельной проверки реплик.

## Приёмка

- Те же содержательные звонки из выборки 25 имеют нормальный конспект без
  заглушки `_compose_manager_brief`; доказательно несодержательный звонок может
  сохранять специальное объяснение своего типа.
- Очевидный согласованный следующий шаг не теряется.
- Технические фразы AMO отсутствуют в пользовательской ячейке.
- Один вызов Analyze, повторного ASR нет.
- Точечные тесты зелёные; сравнительная Google-вкладка обновляется только после
  смысловой проверки всех 25 строк.

## Бритва

Вариант 1, полный откат к v2, отвергнут: он снимает защиту критичных фактов.
Вариант 2, только переставить поля publisher, отвергнут: полезного текста в v3
нет. Выбран минимальный гибрид: свободный конспект плюс прежняя строгая проверка
критичных структурированных полей.

## СТОП

- Нужен повторный ASR, изменение production или второй анализатор.
- Для исправления ослабляется проверка критичных коммерческих фактов.
