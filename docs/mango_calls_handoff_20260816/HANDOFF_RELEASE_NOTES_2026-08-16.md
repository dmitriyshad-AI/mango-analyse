# Mango Calls: M4 handoff release

## Назначение

Эта ветка является единой точкой передачи актуального кода Mango Calls и проверенных ТЗ на MacBook M4. Она не является разрешением на production-deploy.

## Обновление Quality v3 от 17.08.2026

Отдельная ветка `codex/mango-calls-quality-v3-m4-20260816` реализует пять ТЗ
офлайн и передаётся M1 по инструкции
`M1_QUALITY_V3_INTEGRATION_PROMPT.md`. Точный SHA передаётся вместе с итоговым
сообщением владельцу. Реальный Mango transcript, калибровка соответствия
дорожек, пилот 1→10→50→100→200 и включение внешней публикации в эту статическую
приёмку не входят и остаются STOP до отдельного решения Дмитрия.

Первый Analyse по новому prompt-контракту не использует старый cache entry и
может вызвать модель; исторический массовый проход без замера 50 звонков и
согласованного бюджета запрещён. Живой Google-лист с прежними 16 столбцами
требует отдельной миграции до нового 17-столбцового контракта.

Resolve больше не вызывает модель даже в controlled-профиле. Каждая внешняя
попытка Analyse резервируется в БД до вызова, завершается под тем же ID и только
после подтверждённого commit допускается в кэш. Google publisher использует
этот журнал как источник истины и отказывает до любой внешней записи, если
попытка незакрыта, неопределённа или продублирована.

Экономия токенов не снижает модель или глубину: недоверенные и явно
несодержательные звонки пропускают модель, неизменный вход использует штатный
кэш, одна попытка выполняет не более одного внешнего вызова Codex, а параметры
Ollama входят в ключ результата. Неполный usage не объявляется точным.

## Конфиденциальные данные

В Git запрещены рабочие SQLite, аудио, publisher state, manager identity, credentials и env. Если для офлайн-проверки нужен конфиденциальный снимок, он передаётся отдельным DMG без пароля через личный каталог Яндекс.Диска владельца. Целостность проверяется по внешнему SHA-256 и внутреннему manifest.

Mango API credentials и Google service-account key в handoff не входят: M4 не получает права обращаться к живым системам.

## Граница полномочий

M4 работает в новой ветке/worktree и возвращает только код, тесты и аудиты. Любое изменение production M1 выполняется отдельно после независимого ревью и решения GO/STOP.
