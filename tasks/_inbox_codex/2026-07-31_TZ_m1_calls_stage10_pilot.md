# Этап 10: контрольный запуск службы звонков на M1

## Стартовое условие

- текущий Process A на основном Mac штатно завершён;
- код на обоих компьютерах чистый и имеет один SHA;
- `MANGO_CALLS_EXPECTED_CODE_SHA` на обоих компьютерах равен этому SHA;
- выполнены все проверки `docs/M1_MANGO_CALLS_SPLIT_CUTOVER_RUNBOOK.md`;
- владелец отдельно подтвердил переключение служб и перенос runtime;
- SQLite, аудио и секреты не передавались через Git или Яндекс Диск; внутренние
  XLSX/TXT с персональными данными в Яндекс Диске доступны только допущенным.

## Цель

Подтвердить на семи последовательных завершённых сутках, что M1 полностью и
без потери данных выполняет Process A, основной Mac забирает запечатанный пакет
и выполняет Process B, а РОП получает проверенные XLSX, TXT и Google-таблицу.

## Проверки каждого дня

Для каждого дня создаётся owner-only каталог
`~/.mango_local/mango_calls_stage10_evidence/YYYY-MM-DD/` с копиями обезличенных
status/manifest JSON и `daily_verdict.json`. В нём обязательны счётчики
`mango_unique`, `ready_unique`, `quarantine_unique`, `pending_unique`,
`unexplained_missing`, SHA ready-drop, статусы Process B/Yandex/Google и время
каждой стадии. Формула полноты:
`mango_unique = ready_unique + quarantine_unique + pending_unique + unexplained_missing`,
а для зелёного дня `unexplained_missing = 0`; идентификаторы и тексты в этот JSON не включаются.
`mango_unique` берётся только из независимого суточного перечня Mango API или
неизменяемого manifest загрузки, но не из ready-базы. Категории справа взаимно
исключаются: сначала `ready`, затем явный `quarantine`, затем только запись с
явным незавершённым состоянием очереди считается `pending`. Остаток независимого
перечня Mango, которого нет ни в одной из трёх доказанных категорий, считается
`unexplained_missing`; одна запись не может попасть в две категории. Первый подшаг этапа 10
должен реализовать этот агрегатор и тест на искусственном наборе с пересечениями.

1. Mango: число полученных, новых, изменённых, переиспользованных и пропущенных;
   второй проход без новых данных почти пустой и не создаёт дублей.
2. ASR: ровно один Whisper и один GigaAM worker, без параллельного дубля; все
   новые записи имеют оба результата либо явную причину карантина.
3. Resolve/Analyze: нет необработанного хвоста без явной причины; неудачные
   строки остаются в очереди, а не объявляются готовыми.
4. Ready-drop: manifest неизменяем, SHA/размер совпадают, обе проверки SQLite
   возвращают `ok`.
5. Передача: основной Mac принимает ровно это поколение, повтор того же SHA
   идемпотентен, повреждённый или изменившийся пакет блокируется.
6. Timeline: Process B работает только на основном Mac, не пишет в production и
   подтверждает число добавленных/обновлённых строк staging.
7. Отчёт РОП: один завершённый московский день, полный диалог без обрезки,
   корректные роли и ФИО менеджера, сомнительные строки только на листе проблем.
8. Яндекс Диск: XLSX лежит в корне, TXT в неизменяемой подпапке поколения;
   секретов и служебных SQLite там нет.
9. Google: приватная папка, одна таблица на «день + хеш», обратная сверка зелёная;
   после сбоя файл остаётся в карантине и не создаёт дубль при повторе.
10. Ресурсы: свободное место не ниже 40 ГиБ, длительность стадий и максимальная
    память записаны без персональных данных.

## Смысловая проверка

Ежедневно РОП читает случайные 10 разговоров и все строки листа проблем.
Проверяется порядок реплик, роли, фактическая точность краткого содержания,
следующий шаг, бренд и отсутствие выдуманных фактов. Каждая подтверждённая
ошибка превращается в тест, правило проверки или явный ручной контроль.

## Приёмка

- 7/7 дней без потери звонков и дублей;
- 7/7 ready-drop и обратных сверок Google зелёные;
- 0 необъяснённых расхождений между M1 и основным Mac;
- 0 утечек секретов/SQLite/аудио в Git, Яндекс Диск или логи; XLSX/TXT являются
  разрешённым внутренним исключением и проверяются по списку доступа;
- формальная проверка и независимый смысловой аудит пройдены;
- после этого владелец отдельно решает, оставлять ли схему постоянной.

## Стоп-условия

Любое расхождение SHA, `integrity_check != ok`, пропавший звонок, неверная роль,
публичная папка Google, дублирование таблицы, менее 40 ГиБ свободного места или
одновременная работа Process A на двух компьютерах останавливают этап. Live
AMO/CRM/Tallanto write, удаление старого runtime и автоматическая чистка Google
не входят в этот этап.
