# ТЗ: переоценка семейных конфликтов и ручных связей Tallanto

## Цель

Сырые источники остаются инкрементальными, а производные связи семьи и открытые
конфликты переоцениваются по актуальным данным. Общий телефон нескольких детей
одной семьи не должен сам по себе склеивать людей или блокировать семью.

## Порядок

1. Read-only посчитать прогноз до правок: открытые конфликты по типам, затронутые
   клиенты, 601 shared-family-phone по категориям имён, потенциально закрываемые
   конфликты и отдельную очередь возможных дублей. Ничего автоматически не сливать.
2. Исправить импорт посещений Tallanto: подтверждённая вручную точная связь должна
   учитываться наравне с strong_unique через существующий общий источник истины.
3. Запретить слияние разных Tallanto-учеников только по общему телефону.
4. После штатного family_graph_refresh переоценивать открытые identity/family
   конфликты. Закрывать только те, чьё условие исчезло или объяснено одной
   подтверждённой семьёй; настоящие дубли и противоречащие точные ID оставлять.
5. Сделать переоценку идемпотентной. Новых таблиц, флагов, зависимостей и второго
   конвейера не создавать.
6. На staging пересобрать только производные таблицы, без повторного скачивания
   источников и без публикации. Показать было -> стало.
7. Подготовить локально: очередь возможных дублей для владельца и агрегированную
   очередь восстановления карточек без имени/телефона/email с деньгами.

## Критерии готово

- общий телефон двух разных Tallanto student ID сохраняет двух детей в одной семье;
- один и тот же точный Tallanto student ID может быть кандидатом на дубль, но не
  сливается по имени;
- два человека с общим телефоном без семейного доказательства не склеиваются;
- manual-связь участвует в привязке посещений;
- повторный family_graph_refresh не меняет числа после первого ремонта;
- реальные конфликтующие точные ID остаются открыты;
- есть агрегаты до/после и отдельные пять вердиктов formal/semantic/business/data/runtime;
- prod, AMO, Tallanto, CRM, Wappi и клиентские каналы не изменены.

## Приёмка

- точечные тесты из шапки зелёные;
- отрицательный контроль доказывает, что переоценка вызывается живым шагом
  family_graph_refresh;
- staging до/после показывает закрытие только объяснённых конфликтов;
- возможные дубли не объединены и сохранены отдельной очередью;
- повторная пересборка производных таблиц даёт нулевое изменение;
- audit pack содержит сырой агрегированный расчёт, тесты, риски и смысловой аудит.

## СТОП

- обнаружена запись в prod или внешнюю систему;
- общий телефон приводит к автоматическому слиянию разных точных Tallanto ID;
- переоценка закрывает конфликт точного внешнего ID без доказательства;
- staging quick_check не `ok` или foreign_key_check не пуст;
- нужен новый код-путь, таблица, флаг или зависимость вместо расширения живого пути;
- для исправления требуется повторное скачивание источников или тяжёлый полный прогон.
