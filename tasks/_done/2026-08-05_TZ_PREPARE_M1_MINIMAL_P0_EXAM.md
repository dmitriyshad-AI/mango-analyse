# Подготовить минимальный P0-экзамен для M1

## Проблема

Существующее M1-ТЗ закреплено за старым SHA и смешивает обязательный живой
P0-замер с полной переписью regex. Для решения D-103 нужен один воспроизводимый
экзамен существующего модельного поля `is_p0`, а не новый стенд и не ещё один
аудит всего репозитория.

## Образ результата и бизнес-польза

На M1 выполняется ровно один полный прогон готового измерителя по принятому
набору 815. Результат позволяет владельцу принять бинарное решение: модель
становится смысловым владельцем P0 либо старый маршрут сохраняется. Неудачный
результат честно сохраняется и не перезапускается ради красивого числа.

## Порядок

1. Проверить текущий `main`, D-103, существующий измеритель и его тесты.
2. Совместно с Claude, архитектором, ломателем и бизнес-аудитором отделить
   обязательный экзамен от лишней переписи regex.
3. До M1 устранить обнаруженный ложный PASS: добавить уже принятое D-103 поле
   `child_safety` в существующий prompt/нормализатор и в диагностический гейт.
4. Изолировать экзамен от внешнего pilot-profile, даты и неизвестного бренда;
   жёстко сверять ожидаемый Git SHA, текущую модель `gpt-5.5` и reasoning `high`.
5. Проверить набор 815, SHA, состав классов и отсутствие конфликтующих дублей.
6. Выполнить локально только тесты и `--validate-only`, без модельных вызовов.
7. Положить самодостаточный пакет и промт на Яндекс Диск; точное M1-ТЗ оставить
   в Git.
8. Старое избыточное M1-ТЗ пометить superseded штатным `task_move.py`.

## Приёмка

- новый модельный механизм и новый вызов модели не добавлены;
- точный code SHA и SHA набора зафиксированы;
- один full run, один output-каталог, повтор только при доказанном техническом
  сбое и без сокрытия первой попытки;
- PASS проверяет FN/FP, P0-route, `child_safety`, missing/invalid поля,
  автономный P0 и целостность deterministic replay;
- `child_safety=38/39`, неполное replay-покрытие или чужой code SHA не могут
  получить `quality_passed=true`;
- неоднозначные случаи и все расхождения показаны отдельно;
- результат M1 не включает live и не удаляет regex автоматически;
- пакет имеет manifest/SHA256 и готовый копируемый промт.

## Стоп

- для пакета требуется новый модельный механизм, новый вызов модели или правка
  production P0-кода за пределами точного класса `child_safety` из D-103;
- набор, его SHA или состав 298/496/21 не совпали;
- существующий измеритель не может доказать живой model-led route;
- нужен write в AMO, Tallanto, Wappi, CRM или рабочие базы.

## Бритва

Переиспользовать `scripts/run_p0_model_led_m1_eval.py` и готовый набор. Полную
regex-инвентаризацию, Customer Timeline, KB и live-cutover в экзамен не включать.
