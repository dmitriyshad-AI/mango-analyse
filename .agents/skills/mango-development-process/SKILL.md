# Реализация задачи Mango

`AGENTS.md` и разрешения Дмитрия выше этого skill. Он задаёт порядок, а
машинную проверку выполняют штатные скрипты; не переписывай их логику вручную.

## До кода

1. Прочитай актуальные source-of-truth, возьми ТЗ в `tasks/_running` и запусти
   `tz_lint.py`.
2. Сначала спроси Graphify, затем проверь каждый вывод в сыром исходнике.
3. Сними один canonical inventory:

```bash
python3 scripts/skills/inventory_before_build.py \
  --feature-id <Feature-ID> --problem-id <Problem-ID> --change <Изменение> \
  --symbols '<Ключевые-символы через запятую>' \
  --keywords '<Ключевые-слова через запятую>' --out-dir <локальный audit-dir>
```

4. Следуй `decision`: `reuse/extend/port` используют указанного владельца;
   `new` допустим только с `ABSENT_PROVEN`; `stop` запрещает код.
5. Запусти `preflight.py --tz ... --inventory ...`. Его `REQUIRED_ROLES` —
   вычисленный план ролей, не заменяй его ручным `role_plan.json`.

## Роли и контекст

- Любая code-задача: Claude Code Opus, `architect-auditor` и `breaker`.
- Рефакторинг/удаление/поиск дублей: также `cleaner`.
- Клиентский текст, KB, bot, CRM, AMO, Tallanto, Wappi или email: также
  `business-auditor` и отдельный `semantic_pass`.

Claude получает не пересказ чата, а context pack: ТЗ, inventory, HEAD/ветку,
выбранного владельца, релевантные исходники и тесты, актуальные решения и точную
приёмку. Для одинакового `HEAD + prompt_hash + files_hash` повторный внешний
вызов запрещён без записанной причины. Receipt и отчёты ролей входят в audit
pack; если обязательного инструмента нет, остановись, а не объявляй аудит.

## После решения

Правь выбранного владельца минимально. Проверь положительный сценарий,
соседнюю регрессию и враждебный сценарий. Для значимого блока создай один audit
pack. Закрывай не только попытку, но и `Problem-ID`: если исходная проблема не
закрыта, оставь явный следующий шаг. До внедрения этапа C уже открытый диалог
проверяет эти доказательства вручную; после C их проверит `task_move --done`.
